# ZAGATOVKY — админ-кабинет

Рабочее место владельца: каталог, заказы, витрина и настройки.
Отдельное приложение со своим доменом и своим деплоем — витрину не подключает
и её кода не использует, общается только с API.

## Запуск

Нужен работающий API (репозиторий `ZAGATOVKY-Backend`).

```bash
cp .env.example .env      # укажите адрес API
pnpm install
pnpm dev                  # http://localhost:5174
```

Учётка после сида базы: `owner@zagatovky.kz` / `zagatovky123` —
смените пароль сразу (Команда → Пароль).

## Переменные окружения

```
VITE_API_BASE_URL="https://<api>.up.railway.app/api/v1"
```

Vite вшивает `VITE_*` в бандл на этапе сборки, поэтому на Railway это
**build-time** переменная, а не переменная рантайма.

## Что внутри

- **Обзор** — виджеты дашборда, перетаскиваются и скрываются; раскладка хранится
  в профиле на сервере, поэтому переезжает между устройствами.
- **Заказы** — канбан со сменой статуса перетаскиванием и списочный режим.
  Кнопка «Написать» открывает WhatsApp клиента с готовым текстом заказа.
  Заявки, созданные автотестами, помечены и по умолчанию скрыты.
- **Товары** — таблица с правкой цены прямо в ячейке, массовыми действиями,
  выбором колонок и именованными представлениями. Редактор: табы RU/KK,
  загрузка фото перетаскиванием, живое превью карточки как на витрине.
  Для наборов — конструктор состава с расчётом выгоды для покупателя.
- **Медиатека** — общее хранилище фото, файлы переиспользуются между товарами.
- **Главная** — конструктор секций витрины: порядок, видимость, тексты.
- **Настройки** — контакты, доставка, бренд, категории.
- **Команда** — пользователи и роли (`OWNER` / `MANAGER` / `VIEWER`).
- **Журнал** — кто и что менял.

`Ctrl+K` — командная палитра: быстрый переход к товару или заказу.
Тема, плотность интерфейса и акцентный цвет настраиваются в шапке.

## Стек

React 19 + Vite + TypeScript, Tailwind CSS v4, Radix UI, TanStack Query,
dnd-kit (перетаскивание), cmdk (палитра), Zustand.

Типы ответов API не пишутся руками: `src/types/api.ts` генерируется из
OpenAPI-схемы работающего API и коммитится в репозиторий.

```bash
pnpm gen:types                                       # с локального API
API_SCHEMA_URL=https://<api>/docs/json pnpm gen:types
```

## Проверка и сборка

```bash
pnpm typecheck
pnpm build
docker build -t zagatovky-admin --build-arg VITE_API_BASE_URL=https://<api>/api/v1 .
```

E2E-тесты кабинета живут в репозитории витрины (`ZAGATOVKY`, папка `e2e/`) —
они проверяют сквозные сценарии «правка в кабинете → результат на витрине».
