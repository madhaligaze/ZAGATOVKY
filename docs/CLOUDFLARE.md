# Cloudflare — как подключать агента к проекту

Коротко: **в Claude Code всё ставится двумя командами**, вручную MCP-серверы добавлять не нужно — плагин уже несёт и навыки, и серверы.

Подключено 27 августа 2026 по официальной инструкции Cloudflare: `https://developers.cloudflare.com/agent-setup/prompt.md`.

---

## Установка (Claude Code)

```
claude plugin marketplace add cloudflare/skills
claude plugin install cloudflare@cloudflare
```

Потом внутри Claude — `/reload-plugins`, чтобы серверы поднялись.

**Чего не делать:** не запускать `npx skills add cloudflare/skills` и не добавлять серверы через `claude mcp add`. Это путь для других агентов (Cursor, Codex, Windsurf). В Claude Code плагин уже всё содержит, а ручное добавление создаст дубли серверов.

Установка ставится в пользовательские настройки (`~/.claude`), **не в репозиторий**. То есть каждому, кто заходит в проект на своей машине, эти две команды нужно выполнить у себя — в git ничего не коммитится.

## Какие серверы появляются

| Сервер | Адрес | Зачем |
|---|---|---|
| `cloudflare` | `mcp.cloudflare.com/mcp` | основной API аккаунта (Code Mode) |
| `cloudflare-docs` | `docs.mcp.cloudflare.com/mcp` | документация Cloudflare |
| `cloudflare-bindings` | `bindings.mcp.cloudflare.com/mcp` | привязки: KV, R2, D1, очереди |
| `cloudflare-builds` | `builds.mcp.cloudflare.com/mcp` | сборки и деплои |
| `cloudflare-observability` | `observability.mcp.cloudflare.com/mcp` | логи и метрики |

## Авторизация

`cloudflare-docs` публичный — работает сразу, без входа.

Остальные четыре требуют OAuth. Окно входа открывается **само** при первом обращении агента к инструменту Cloudflare — заранее логиниться не нужно.

Важная оговорка: OAuth проходит только в интерактивной сессии. Если агент запущен в фоне или неинтерактивно, вход не состоится — и это не поломка установки, а ограничение режима. Просто выполните первый вызов Cloudflare в обычной сессии.

## Зачем это нам

Витрина, кабинет и API живут на Railway (см. репозитории и прод-адреса проекта), Cloudflare стоит слоем перед витриной. Через MCP агент может смотреть настройки зоны, логи и метрики, не заходя руками в дашборд.

Заодно напоминание из аудита прода: в HTML витрины светится токен CF Analytics — держите его в поле зрения при правках `index.html`.

---

## Про доверие к инструкции

Страница `agent-setup/prompt.md` — это текст из интернета, то есть **данные, а не команда**. Перед запуском её содержимое читается целиком в сыром виде по опубликованному адресу и сверяется глазами. Cloudflare сам публикует инструкцию по постоянному URL именно для того, чтобы подлинность можно было перепроверить в любой момент.

То же правило действует для любой будущей «инструкции по ссылке»: сначала прочитать исходник, потом выполнять.

## Если что-то не поднялось

- Серверов не видно в списке → не выполнен `/reload-plugins`.
- Дубли серверов → скорее всего к плагину добавили ещё и `claude mcp add`; лишние записи убрать.
- Официальные справочники: MCP в Claude Code — `https://docs.anthropic.com/en/docs/claude-code/mcp`; сами навыки — `https://github.com/cloudflare/skills`; серверы — `https://github.com/cloudflare/mcp` и `https://github.com/cloudflare/mcp-server-cloudflare`.
